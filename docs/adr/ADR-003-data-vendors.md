# ADR-003：数据供应商与来源选择

- 状态：已接受
- 日期：2026-09-26
- 关联：ARCHITECTURE.md §5.1、§15

## 背景

MVP 使用 AKShare（开源、免费、聚合多家网站）。2026-09 的探测和审计发现：

- 东方财富行情类主机（push2/push2his：`stock_zh_a_hist`、`stock_zh_a_spot_em`、`stock_zh_index_daily_em`）从本机被持续断开连接；东方财富数据中心（`datacenter-web`，如 `stock_tfp_em`）可用。
- 旧实现在东方财富第一次失败后，把本次运行剩余证券全部切到腾讯，导致同一证券的历史拼接了两种来源（17 只）。
- AKShare 1.18.78 的若干适配器缺陷直接污染了标准数据（见下）。

## 决定

每个数据集固定一个来源，不在运行中途切换：

| 数据集 | 来源 | 备注 |
|---|---|---|
| 交易日历 | 新浪 `tool_trade_date_hist_sina` | 含未来交易日，用于判断"今天是否交易日" |
| 证券主数据 | 上交所、深交所、北交所列表及退市列表 | 见 ADR-001 |
| 沪深日线（不复权） | 腾讯 `stock_zh_a_hist_tx` | 含退市证券 |
| 北交所日线 | 新浪 `stock_zh_a_daily`；退市证券用 `stock_zh_a_cdr_daily`（仅历史接口） | 包装器的股本请求对退市代码失败 |
| 复权因子 | 新浪 hfq-factor | 无新浪因子时，用新浪历史中的除权参考价 `prevclose` 推导（见 ADR-004） |
| 指数日线 | 腾讯 `stock_zh_a_hist_tx` | |
| 停复牌 | 东方财富数据中心 `stock_tfp_em`（每次运行快照）+ 百度 `news_trade_notify_suspend_baidu`（逐日，2023-01-03 起） | 只追加，不覆盖 |
| 深市简称变更 | 深交所 `stock_info_sz_change_name` | 用于带日期的 ST 历史 |
| 全市场快照 | 东方财富，失败则腾讯 | 单次调用，按抓取时间标注交易日 |

适配器层的已知缺陷及处理：

1. **腾讯成交量单位**：AKShare 对 `sh688/sz399/sh000/sz000` 前缀不乘 100，因此深市主板 000xxx 股票停留在"手"，而 689xxx CDR 被多乘一次 100。标准化层按规则修正并记录 `volume_scale`；另有阻断规则要求每只证券 `成交额/(成交量×收盘价)` 的中位数在 [0.5, 2]。
2. **腾讯指数成交量**是"手"，标准层统一为"股"（`volume_shares`）。
3. **多处 HTTP 调用没有超时**（新浪因子/历史、腾讯起始年份查询）：进程内为 `requests` 安装 30 秒默认超时。
4. **重试分类**：只重试网络/传输错误；解析类错误（如 `KeyError('day')`、`ValueError('sina hfq factor not available')`）立即判定失败，不再浪费 7 秒退避。

## 理由

来源固定可以保证同一序列的单位、取整和除权口径一致；东方财富被阻断时，腾讯和新浪能覆盖全部需求。

## 风险

- AKShare 声明数据仅供学术研究；所有来源都是网站接口，可能随时变化或限流。**进入模拟盘前必须评估商业数据源**（交易所授权或持牌供应商），本 ADR 届时复审。
- 腾讯日线的成交量已取整到"手"，成交额取整到 100 元。
- AKShare 版本固定为 1.18.78；升级前必须先跑测试和小样本采集，再对照本 ADR 的缺陷清单逐项验证。

## 复审条件

AKShare 升级、东方财富恢复可用、引入付费数据源，或任一来源连续失败时复审。
